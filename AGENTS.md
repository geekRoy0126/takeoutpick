# TakeoutPick — Agent Rules

## 0. Start here (every task)

1. Read the GitHub issue you are implementing, then its user story in `docs/PRD.md` §5 and, for UI work,
   `docs/ui-spec.md`. Restate the acceptance criteria (AC) as a checklist before writing code.
   No GitHub access? The issue's AC are the matching user story's AC in `docs/PRD.md` §5 (issue numbers in brackets).
2. **Scope = every AC of the issue.** A one-line request in chat ("implement #5") is a pointer to the issue, not a
   smaller scope: implement all of its AC. Never drop an AC silently. If one is truly blocked, say so in your plan
   *before* writing code and wait for an answer.
3. Work on exactly one issue per branch. Do not add features, screens or fields the issue does not ask for.
4. Follow TDD (§3.4): write failing tests first, show their failing output, then implement.
5. Missing infrastructure is not a reason to skip a layer. No database running? Still write the service and its
   `*.int.test.ts`, commit them, and report them as "written, not run" with the command to run them.
6. If the request conflicts with this file, the PRD or `prisma/schema.prisma`, stop and ask. Do not guess.
7. Finish with the Definition of Done (§7) and summarize: files changed, tests added, commands run with results,
   and every AC as `[x]` or `[ ]` with the reason.

## 1. Project context

<!-- Why: without this, agents assume a generic CRUD app and miss the pricing rules that are the whole product. -->

TakeoutPick helps students decide what takeout to order in seconds by comparing the **true total cost**
(after deals, fees, tip and tax), **health level** and **variety**. P2 turns the Project 1 single-user prototype
into a multi-user app with three roles — **Diner**, **Partner** (restaurant staff), **Admin** — plus real-time
**Group Pick** rooms and a documented **public REST API**.

### 1.2 Version traps — your training data is probably older than this stack

- **Next 16:** route protection lives in `src/proxy.ts` exporting `proxy()` (not `middleware.ts`).
  `cookies()`, `headers()`, `params` and `searchParams` are async — always `await` them.
- **Cache Components is on.** Never export `dynamic`, `revalidate` or `fetchCache` from a route (build error).
  A Server Component that reads cookies, headers or the database renders inside `<Suspense>` with a skeleton
  fallback. `new Date()` / `Date.now()` in a Server Component must come after `await connection()` inside that
  Suspense boundary — or pass `now` in from a Client Component. Cache shared reads with `"use cache"` + `cacheLife`.
- **Prisma 7:** import the client from `@/generated/prisma/client`, never from `@prisma/client`. Use the shared
  `db` from `@/lib/server/db`. The database URL lives in `prisma.config.ts`, not in the schema.
- **Tailwind 4:** design tokens are CSS variables in `src/app/globals.css` (`@theme`). There is no config file.
- **zod 4:** use `z.email()`, `z.url()`, `z.iso.datetime()`; custom messages use `{ error: "..." }`.

### 1.3 Architecture

```
src/
  app/                    Routing and composition only
    (auth)/               login, register pages
    restaurants/ pick/ compare/ orders/ rooms/   Diner pages
    partner/              PARTNER pages (guarded)
    admin/                ADMIN pages (guarded)
    api/v1/               Public REST API route handlers (thin)
    api-docs/             Swagger UI page
  components/
    ui/                   Generic primitives: Button, Card, Pill, Dialog, EmptyState, Skeleton
    <feature>/            deals/, pricing/, restaurants/, compare/, pick/, rooms/, partner/, admin/
  lib/
    domain/               PURE business logic: pricing, deals, recommend, variety. No I/O.
    server/               `import "server-only"` code: db.ts, auth/, services/, realtime.ts
    validation/           zod schemas shared by API routes, Server Actions and forms
    api/                  http.ts — ok(), errorResponse(), ApiError, parseOrThrow()
  generated/prisma/       Generated client (git-ignored, never edit)
  proxy.ts                Redirects logged-out users away from guarded pages
prisma/                   schema.prisma, migrations/
tests/integration/        *.int.test.ts against real Postgres
e2e/                      Playwright specs
docs/                     PRD.md, ui-spec.md, standups/, retros/
```

Request flow — every feature follows it:

```
Page / Client Component ──► Server Action (app/**/actions.ts) ─┐
External client ─────────► Route handler (app/api/v1/**)  ─────┼─► service (lib/server/services/*-service.ts)
                                                                │        ├─► domain functions (lib/domain, pure)
                                                                │        └─► db (Prisma) ──► Postgres
Pusher ◄── realtime.ts ◄────────────────────────────────────────┘   (services publish after a successful write)
```

- **Route handlers and Server Actions are thin:** authenticate → `parseOrThrow(schema, input)` → call one service →
  return `ok(data)`; wrap the body in `try/catch` and return `toErrorResponse(err)`.
- **Only services import `db`.** Services enforce authorization (role and ownership) themselves; `proxy.ts` only
  redirects and is never the only check.
- **Domain functions are pure:** no imports from `next`, `react`, Prisma or `@/lib/server`; money in and out as
  integer cents. They are the most heavily tested code.
- **Time is always passed in.** `now: Date` is a *required* parameter — never a default such as
  `now = new Date()` (that hides the clock, makes tests depend on the real time and breaks Cache Components).
  Read the clock once per request: in the service (`const now = new Date()`) or in a Client Component, then pass
  `now` or the computed result (e.g. `status`) down. Components never read the clock themselves.
- **Server Components by default.** Add `"use client"` only to the smallest interactive leaf.
- **Real-time:** after a Group Pick write commits, the service calls `publishRoomSnapshot(code)` which sends the
  whole room state on channel `room-<code>`, event `room.updated`. Clients replace their state with the snapshot
  (idempotent; no client-side merging).

### 1.4 Naming conventions

| Thing | Convention | Example |
| --- | --- | --- |
| Files and folders | kebab-case — **also for component files** | `deal-badge.tsx` (not `DealBadge.tsx`) |
| Next special files | As Next requires | `page.tsx`, `route.ts`, `actions.ts` |
| React components | PascalCase name, **named** export, one per file | `export function DealBadge()` in `deal-badge.tsx` |
| Props and DTO types | `type` alias, not `interface`; props end in `Props` | `type DealBadgeProps = { … }` |
| Services | `<noun>-service.ts`, verb-first functions taking `now` when time matters | `listDeals({ status, now })` |
| Functions, variables | camelCase; booleans start with is/has/can | `getDealStatus`, `isExpired` |
| Constants | SCREAMING_SNAKE_CASE | `EXPIRING_SOON_HOURS = 72` |
| Money / rates | `*Cents` integers, `*Percent` whole numbers, `*Bps` basis points | `minOrderCents`, `taxRateBps` |
| Time fields | `*At`, stored UTC | `expiresAt` |
| zod schemas + types | `xxxSchema` and `type Xxx = z.infer<typeof xxxSchema>` | `createDealSchema`, `CreateDeal` |
| API paths | `/api/v1/<plural-noun>`, JSON keys camelCase | `/api/v1/deals?status=active` |
| Pusher | channel `room-<code>`, event `room.updated` | `room-K7Q2XM` |
| Tests | `*.test.ts(x)` beside the file; `*.int.test.ts`; `e2e/*.spec.ts` | `deals.test.ts` |

No default exports except Next special files. No `I` prefix on types. No abbreviations beyond `id`, `url`, `db`.

### 1.5 Coding standards

- TypeScript strict: no `any` (use `unknown` + narrowing), no `!` non-null assertions outside tests, no `@ts-ignore`.
- Validate every external input with zod at the boundary: request bodies, query strings, params, form data, env.
- Never compute money with floating-point dollars. Use `@/lib/domain/money` (`formatCents`, `percentOf`,
  `basisPointsOf`) and follow the pricing rules in `docs/PRD.md` §4 exactly, including rounding at each step.
- Keep functions under ~40 lines and files under ~200 lines; split by responsibility, not by layer count.
- Comments explain *why*. Link non-obvious decisions to their issue: `// Ties go to the lower total (#9).`
- Every TODO has an issue: `// TODO(#12): paginate`. No orphan TODOs.

### 1.6 Testing strategy

<!-- Why: the P2 rubric grades TDD visible in git history, plus unit + integration + E2E. These rules make the
     agent produce exactly that evidence. -->

| Level | Tool | What | Where |
| --- | --- | --- | --- |
| Unit | Vitest + jsdom + Testing Library | Every domain function; components' visible behavior | Beside the file |
| Integration | Vitest (node) + real Postgres | Services and route handlers end to end through Prisma | `tests/integration/` |
| E2E | Playwright (desktop + Pixel 7) | One happy path per user story, plus auth guards | `e2e/` |

- **One test per AC checkbox at minimum,** named after it:
  `it("shows 'Add $5.01 more' when the subtotal is $14.99 and the minimum is $20")`.
- One test file per source file, same base name, beside it (`deal-badge.tsx` → `deal-badge.test.tsx`). No
  catch-all `deals.test.tsx` that tests several components.
- Vitest globals are off, so `vitest.setup.ts` calls Testing Library's `cleanup()` after each test. Don't add a
  second cleanup in test files.
- Cover boundaries named in the PRD: exactly 72 h before expiry, exactly at expiry, subtotal exactly equal to the
  minimum, amount-off larger than the subtotal, 0% and 100% discounts.
- Use fixed dates (`new Date("2026-11-03T12:00:00Z")`) — never the real clock in unit tests. Only exception:
  an integration test that calls a route handler (which owns `now`) may seed data relative to `Date.now()`, at
  least 1 hour away from any boundary; test the exact boundaries through the service with a fixed `now`.
- Query the DOM by role and label (`getByRole`, `getByLabelText`); no `data-testid` unless nothing else works.
  Use `@testing-library/user-event`, not `fireEvent`.
- Integration tests use a real database (`docker compose up -d db`) and clean their tables in `beforeEach`.
  Do not mock Prisma or `@/lib/server/db` — not even in a unit test of a route handler; a route handler is
  tested in `tests/integration/<route>.int.test.ts`. Mock only external services (Pusher) with
  `vi.mock("@/lib/server/realtime")`.
- Never `vi.useFakeTimers()` / `vi.setSystemTime()` to fake "now" for domain code; pass `now` instead (§1.3).
- Coverage: ≥ 80% lines, branches and functions on `src/lib/domain` (enforced in `vitest.config.mts`).
- Commands: `npm test` (unit) · `npm run test:int` · `npm run test:e2e` · `npm run test:coverage`.

### 2.1 What the prototype looks like (summary of `docs/ui-spec.md`)

- Mobile first (375 px), warm and calm: one tomato brand color, warm greys, white space, rounded cards.
- Totals before menu prices. Tap a total on a phone (hover/focus on desktop) to reveal the breakdown.
- Restaurant cards carry a deal badge; dish cards show "Last had: N days ago" or "New to you".
- "Healthiest" appears only when compared options differ in health level. Compare is a table ≥ 768 px, cards below.
- Pick for me asks at most 3 button questions; no typing.
- Status is always color **plus** a word or icon. Tap targets ≥ 44 × 44 px.

### 2.2 Key components (full table in `docs/ui-spec.md` §3)

`DealBadge` (Active / Expiring soon / Expired + Official/Community tag) · `PriceWithDeal` (struck-through before,
bold after) · `MinOrderHint` ("Add $X.XX more to use this deal", `aria-live="polite"`) · `PriceBreakdown` ·
`HealthTag` · `DishCard` · `RestaurantCard` · `CompareView` · `PickWizard` · `RoomPanel` · `EmptyState`.
Reuse these names and locations; check `src/components` before creating a new one.

### 2.3 User flows to implement step by step (details in `docs/ui-spec.md` §4)

1. **Pick for me:** budget → health goal → cuisine or "Surprise me" → top pick + 2 alternatives → "I ordered this"
   → toast with Undo.
2. **Deal-aware browsing:** restaurants (cuisine chips) → restaurant → dish totals → breakdown → quantity →
   live `MinOrderHint`.
3. **Group Pick:** start room → code + share link → join → nominate (≤ 2) → vote (1, changeable) → live counts →
   host closes → winner for everyone.
4. **Become a partner:** "I run this restaurant" → pending → admin approves → Partner nav appears.
5. **Moderation:** Admin tabs Requests · Deals · Users.

Every screen has loading (skeleton), empty (`EmptyState`) and error (inline message + Retry) states.

## 3. Scrum and Git workflow

<!-- Why: issues, branches, commits and PRs are how the graders (and our partner) trace AI-written code back to a

### 3.1 Board

GitHub Project columns: **Backlog → Sprint Todo → In Progress → In Review → Done**. Milestones `Sprint 1`
(Oct 31 – Nov 5) and `Sprint 2` (Nov 6 – Nov 11). Moving a card is the human's job; the agent mentions which move is due.

### 3.2 Branches

`<type>/<issue-number>-<short-kebab-summary>` from an up-to-date `main`.
Types: `feature`, `fix`, `chore`, `docs`, `test`, `refactor`, `experiment`.
Examples: `feature/5-deal-status`, `fix/23-tip-rounding`, `chore/2-ci-pipeline`.

### 3.3 Commits

Conventional Commits with the issue number as the scope:

```
<type>(#<issue>): <imperative summary, ≤ 72 chars>

<optional body: why, not what>
```

Types: `test`, `feat`, `fix`, `refactor`, `chore`, `docs`, `ci`. Examples:

```
test(#5): add failing tests for deal status at the 72-hour boundary
feat(#5): compute deal status and price after deal
refactor(#5): extract applyDeal from PriceWithDeal
```

### 3.4 TDD order (required — graded from git history)

1. `test(#n): …` — commit the new tests **while they fail**. Paste the failing `npm test` output into the PR.
2. `feat(#n): …` — the smallest implementation that makes them pass.
3. `refactor(#n): …` — clean up with tests green.

Never put tests and implementation in one commit. Never weaken or delete a test to make it pass.

### 3.5 Pull requests

- One PR per issue. Title = the main commit title. Body follows `.github/pull_request_template.md`:
  `Closes #n`, what changed, how it was tested (commands + results), screenshots for UI (phone + desktop),
  AI usage notes, checklist.
- Required: CI green and **one approving review from the partner** (the author never self-merges).
- Merge with **"Create a merge commit" or "Rebase and merge" — never "Squash and merge"** (squashing erases the
  failing-test commits).

### 3.6 Referencing issues

- In commits: the scope `(#n)`. In PR bodies: `Closes #n` (auto-closes on merge). In code: only for non-obvious
  decisions and TODOs, as in §1.5.

## 4. Do

- Reuse before creating: `ok`, `errorResponse`, `ApiError`, `parseOrThrow`, `formatCents`, `percentOf`, the
  design tokens and existing components.
- Put business rules in `src/lib/domain` and test them there first.
- Return DTOs from services (explicit `select`), never whole Prisma rows to the client.
- Format dates and money with `Intl` in the UI; keep raw values (cents, ISO UTC) in data.
- Preferred libraries: zod, jose, bcryptjs, Prisma, Pusher, `lucide-react` icons, `swagger-ui-react`,
  `@axe-core/playwright` for accessibility checks.
- These preferred libraries are **pre-approved**: add one in the PR that first needs it (`npm i <name>`) and name it
  in the PR. If the install is impossible (no network), use an inline `<svg aria-hidden="true">` and leave
  `// TODO(#n): switch to lucide-react` — don't stall and don't fall back to emoji.
- Ask before adding any other dependency; name it and the reason in the PR.
- A new route handler follows the full flow of §1.3 even when it is small: zod query schema →
  `<noun>-service.ts` (owns `db` and `now`) → domain function → `ok()`. Example for #5:
  `GET /api/v1/deals` → `listDeals({ status, restaurantId, now })` in `src/lib/server/services/deal-service.ts`.

## 5. Don't

- Don't use `next-auth`/Auth.js, `axios`, `moment`/`dayjs`, `lodash`, Redux, CSS-in-JS or Jest — we already have
  JWT via jose, `fetch`, `Intl`/`Date`, native JS, React state, Tailwind and Vitest.
- Don't call `db` from components, pages, route handlers or Server Actions — go through a service.
- Don't call `new Date()` or `Date.now()` inside `src/lib/domain`.
- Don't use floats for money, raw hex colors, inline `style` for theming, or `dangerouslySetInnerHTML`.
- Don't use `$queryRawUnsafe`/`$executeRawUnsafe`; use the Prisma query API.
- Don't add `.skip`/`.only`, disable lint rules, or lower coverage thresholds to get CI green.
- Don't edit `src/generated/**` or migrations that are already on `main`.
- Don't commit `.env`, secrets, tokens or test credentials; never log passwords or JWTs.

## 6. Security and accessibility requirements

### 6.1 Security

- **Sessions:** JWT signed with `jose` (HS256), secret from `JWT_SECRET` (≥ 32 chars, validated at startup),
  claims `{ sub, role }`, 7-day expiry. Browser: cookie `tp_session`, `httpOnly`, `secure` in production,
  `sameSite: "lax"`, `path: "/"`. `/api/v1/*` also accepts `Authorization: Bearer <jwt>`.
- **Passwords:** `bcryptjs` cost 12. Login failure message is always "Email or password is incorrect."
- **Authorization:** every mutating service checks role (`requireRole`) and ownership (a partner only touches their
  own restaurant). Wrong role → 403, no session → 401.
- **Output:** never return `passwordHash` or another user's email. Unknown errors → generic 500 (`toErrorResponse`).
- **Input:** zod on every boundary; string length limits on every text field (names ≤ 80, notes ≤ 500).
- **Supply chain:** `npm audit --audit-level=high` must pass; new dependencies need partner approval in the PR.

### 6.2 Accessibility (WCAG 2.1 AA)

- Semantic HTML: `<button>` for actions, `<Link>` for navigation, one `<h1>` per page, landmarks.
- Every input has a visible `<label>`; errors are linked with `aria-describedby`.
- Visible focus ring (`focus-visible:outline-2 outline-brand-600`); everything works by keyboard.
- Status never by color alone; text contrast ≥ 4.5 : 1. Verified pairs (v1.1) — use only these for small text:
  `text-surface` on `bg-deal-active` / `bg-deal-soon` / `bg-deal-expired` / `bg-health-*`, and `text-deal-*` /
  `text-health-*` on `bg-surface` or `bg-surface-muted`. Never lower contrast with `opacity-*` on text; show
  "Expired" with the `deal-expired` token instead.
- Live regions (`aria-live="polite"`) for changing totals, `MinOrderHint` and Group Pick vote counts.
- Tap targets ≥ 44 × 44 px; respect `prefers-reduced-motion`.
